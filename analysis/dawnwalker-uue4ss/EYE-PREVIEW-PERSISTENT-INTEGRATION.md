# Persistent native eye preview integration

The next implementation should retain the private renderer between requests and serialize preview updates, capture, and cleanup on the game thread. It must keep the live eye baseline separate from disposable preview resources. Passing the nine-phase V4 experiment alone does not justify mounting the current `ReadyEyeSession`: frame freshness, visible eye semantics, repeated operation performance, and relevant form/restoration evidence remain independent requirements.

## Implemented controller boundary

`probes/DawnwalkerEyePreviewSession.lua` is a new, uninstalled controller. Importing or constructing it performs no native calls. It does not change frozen V4, import the live eye pilot, provide Electron IPC, manufacture a model, publish `EyePreviewFrame`, or construct a ready session. All results explicitly retain `production_ready=false`.

The public methods are `open(request)`, `enqueue(request)`, `renew(address)`, `step()`, `close(address, reason)`, and `shutdown()`. Only the owner of the current lease can queue, renew or close it. Shutdown belongs to the native host, not an arbitrary renderer message. Every operation checks game-thread context; nested operations reject. The initial request and each later update contain:

| Field | Meaning |
| --- | --- |
| `owner_id` | Main-process window/session owner; never selected from an arbitrary webpage. |
| `lease_id` | Fresh opaque request lease; never reused within this controller. |
| `identity_key` | Adapter-generated current build/boot/world/pawn/form/wolf/appearance/head/material generation fingerprint. |
| `view_revision`, `eye_revision` | Independently monotonic integers for the complete desired state. Reusing either revision with different corresponding values rejects. |
| `view` | Existing UI shape: `framing`, `yawDegrees`, `zoom`. Yaw must be finite and inside −69..69; actual framing-specific zoom bounds are validated by the adapter. |
| `settings` | Complete canonical eye settings checked by the runtime owner's schema validator. No native object pointers or arbitrary paths are accepted. |

The controller copies bounded plain payloads, retains one latest desired state and at most one pending state, and runs one synchronous native operation at a time. Repeated updates replace waiting work. Idle captures can refresh the pose, but cannot exceed the configured interval. Defaults are a three-second lease, 100 ms minimum capture interval, 120 frames, and 30 seconds maximum lifetime. These are bounded pilot settings, not measured performance or a smoothness claim. Configuration is capped at a ten-second lease, two-minute lifetime, 1200 frames, and a minimum 16 ms interval. A loop must continue calling `step` while a lease exists so expiry is actually enforced.

The controller rechecks lifetime, source identity and private ownership before mutation, after readback, and after capture. An identity change or expired lease discards queued work and any just-produced evidence. Cleanup is called once for the returned owned handle. An unacknowledged cleanup blocks further opens and retains the failed handle for explicit native recovery; it is never silently retried against a possible replacement receiver. A factory must perform its own partial-construction cleanup; an exception or nil return without a usable handle conservatively locks out further opens because cleanup is unconfirmed. Later close/shutdown calls continue to report that unresolved failure. Closing a healthy lease is idempotent.

## Native adapter extraction

`probes/DawnwalkerPrivateEyeRenderer.lua` now implements the native factory, configuration, geometry, preview MID setters/getters, capture, and cleanup as a separate uninstalled adapter. The V4/V5 candidates remain immutable. The actual V5 private factory failed before rendering and its immediate actor cleanup was unconfirmed, so this extraction is not native rendering proof or a ready UI session. The controller expects these adapter functions:

| Adapter | Required behavior |
| --- | --- |
| `is_game_thread()` | True only on the verified EngineTick game thread. |
| `monotonic_ms()` | Clock used only for scheduling and lease budgets. It is never a claimed capture timestamp. |
| `inspect_identity()` | Resolve the actual local controller's current pawn and return its full validated generation key. Address/name alone is not an epoch: invalidate on observed world/pawn teardown, form/wolf or source binding replacement. |
| `validate_view(view)` | Validate against this actual model's derived profile limits, using the agreed zoom mapping below. |
| `validate_settings(settings)` | Validate the exact canonical material parameter schema without truncating creator presets or inventing iris-color semantics. |
| `create_preview(identity_key)` | Return one owned handle only after successful native private actor, target, clones, lights and independent preview-eye MID setup; clean partial resources on failure. |
| `verify_private_preview(handle, identity_key)` | Check original world/actor/capture/target ownership, main-view isolation, loaded model/source generation, and that both preview eye bindings are private and cannot alias live MIDs or static assets. |
| `update_preview(handle, desired)` | Refresh source pose/framing as necessary, update only private clone MIDs and capture transforms, then return actual camera and parameter getter observations. It receives a copy of desired state. |
| `validate_readback(readback, desired, handle)` | Compare actual native values and resource identity to the request under canonical tolerances. Request echo is insufficient. |
| `capture_preview(handle, readback, sequence)` | Perform one actual native capture and produce immutable evidence from the same owned target. Capture/export ordering and metadata must be bound to this exact readback and sequence. |
| `can_capture(handle)` | Optional capacity check. False retains the newest pending request without native updates/exports while lease expiry remains enforced. |
| `validate_capture_evidence(evidence, readback, sequence, handle)` | Check the native producer's actual identity, sequence, settings/view revisions and readback correspondence. This is not permission to invent a completion timestamp. |
| `release_preview(handle, reason)` | Cancel its timer/queued capture work, detach target, end only owned actors/components, release only owned transient targets/MIDs, and return `owned_cleanup_acknowledged` plus explicit pending/invalidation diagnostics. Never restore the player's eyes here. |

The `create_preview`/`verify_private_preview` requirements deliberately exceed V4's borrowed eye material bindings. Before any preview-only edit, create a separate MID for each preview eye slot. Parent it to the verified original static eye material and initialize the supported effective values from the current live observation. Do not parent the preview to the live controller's changing MID or write its parameters. Other borrowed head/skin/hair material references remain read-only. The live controller retains its own original bindings and live MIDs independently. Rendering close/reset/hide cleanup must not discard or overwrite that live baseline.

The implemented adapter uses the native `DawnwalkerHumanEyeBindings` registry's `inspect`, `verify`, and `validate_settings` seam. Its eight editable UV scalars use each eye's independently observed primary/secondary intervals. Private clone MIDs parent the original MIC, with exact native outer/slot/parent checks; every scalar is read back through its native parameter-info getter. Ordinary player movement refreshes clone transforms and the three cached Head/eye sockets, while foreign material/asset/owner replacements reject. Neither adapter nor session invokes the registry's live `apply` or `restore` methods.

Create a fresh renderer and session controller per preview lease/nonce; retain the shared human binding registry across ordinary hides/reopens so its original live baseline remains stable. Each renderer owns one construction attempt, and its exact frame filenames are `eye-live-<nonce>-<sequence padded to four digits>.png` beneath the fixed boot directory. It retains at most two pending filename records, never PNG buffers. The host must securely consume and remove an exact known file before calling `acknowledge(sequence, file_name)`. Cleanup receipts retain the bounded pending-file ledger plus nonce/boot even when native export throws after creating a partial file. Do not enumerate arbitrary matching filenames for cleanup. A later `observe_cleanup()` is read-only evidence; it does not retroactively turn an unacknowledged release into success.

After owned construction, `describe()` returns only plain native identity/configuration evidence and both framing modes' normalized `zoom_bounds` (`min`, `max`, `initial=1`). It includes no native UObject/FName/parameter-info wrappers and leaves the UI's interaction step to the host. The descriptor is not a ready session and supplies no fabricated frame timestamp or form support. The host still needs the independent live binding schema, actual resource lifecycle proof and a matched validated frame before mounting anything.

The one-shot V4/V5 `verify_sources` compares exact original source bindings across its short operation. Do not carry that rule unchanged into the persistent adapter: a legitimate live apply replaces the original player eye binding with the live controller's own verified MID. The shared baseline owner must explicitly recognize both its original binding and its current owned MID generation, retain a stable canonical UI material ID, and serialize that authorized transition with preview work. A foreign MID/parent/slot swap or unrecognized form/appearance change still invalidates the session. An authorized live apply must not invalidate its own preview merely because its pointer differs from the original static material.

For normalized UI zoom, use `distance = profile.default_distance / zoom`; therefore `initial = 1`, `min = default_distance / maximum_distance`, and `max = default_distance / minimum_distance`. Derive each framing's step from its actual range and validate in both directions. `Reset View` is head-and-shoulders, yaw zero and zoom one. The persistent adapter must refresh a moving/animated source's private pose and pivot without treating ordinary movement as an appearance generation change or moving the actual player/camera. Changes to mesh/asset/material generation invalidate instead of silently rebuilding around stale pending settings.

The bundled UE4SS documentation describes cancellable `LoopInGameThreadWithDelay`, `ExecuteInGameThreadAfterFrames`, and `CancelDelayedAction` in `stage-zdev/ue4ss/Docs/lua-api/global-functions/delayedactions.md`. Verify these functions on the actual installed runtime before use. Keep all native work on the already authorized EngineTick route; do not use async-thread UObject writes. Open and initial capture should be separate scheduled callbacks so newly registered components have an opportunity to publish rendering state. If required native timer/lifecycle support is absent, report that missing operation rather than registering speculative hooks or altering gameplay.

## Host and frame transport

`DawnwalkerEyeSessionHost.lua` now provides the uninstalled composition prototype. `Host.new(config, platform, modules)` is inert; an attested loader must explicitly call `start()` on the reviewed EngineTick route after the host creates and validates the fixed directories. `Host.from_native(config)` connects the actual UEHelpers local-player selector, native frame counter, `ExecuteInGameThreadAfterFrames`, `CancelDelayedAction`, and world-bound `GameplayStatics:GetRealTimeSeconds`. It does not install hooks, start itself, or load the old gameplay bridge. Actual continuous scheduling and clock behavior still need native proof.

The configured one-owner channel is `qa/eye-appearance/native-channel/<boot>/<owner>/`. Host owns `command.tmp` and atomically publishes `command.txt`; native ignores the host temporary slot. Native publishes `channel.ready` once and each `response.txt` via its fixed `response.tmp`. Ready fields are exactly wire version1, boot/owner, current build/executable hash, `transport=eye-session-prototype`, and `production_ready=false`. No global ready index or request-supplied path exists. The host consumes a stable validated response, removes its exact stable command first, then the response. Native never deletes or enumerates channel files. Standard native Lua I/O uses bounded double reads and fixed fresh output checks; it does not claim reparse-point or exclusive-open guarantees. The Node channel owner must validate the directory ancestry and immutable file identity at its side.

One future-frame callback is scheduled at a time, guarded against synchronous or duplicate delivery. Native poll pacing defaults to100ms, and each poll runs lease maintenance even while a response blocks command processing. World replacement, clock regression, scheduler failure and publication failure stop preview work, preserve exact files for host cleanup and report cleanup failure when applicable. One shared human baseline registry survives ordinary preview opens; each new lease gets a new renderer and session. This prototype channel is deliberately bound to one boot/world/owner and does not silently restart after stop or adopt a new world.

`Session.cancel(address)` clears pending work and suspends the latest-request fallback without changing committed live eyes. It retains revision watermarks; invalid/stale/conflicting enqueues cannot resume it, while a fresh valid enqueue can. `Session.maintain()` checks expiry and identity loss without updating or capturing. The dispatcher supplies command-sequence replay protection and calls maintenance through its watchdog. Sixteen host groups and twenty-five session groups cover these paths, including response backpressure, resource cleanup errors, native-route loss, duplicate callbacks and cancellation without replay. Both modules remain outside the frozen candidate and production UI.

The parent of `EyeAppearance` should own session opening, renewal, invalidation and closing. The component's existing `subscribeFrames` and `cancelQueued` methods alone cannot keep native resources safely leased. Suggested private host operations are `eye:open`, `eye:renew`, `eye:close`, `eye:preview`, `eye:apply`, `eye:restore`, `eye:inspect`, and `eye:frame-ack`. Their main/preload implementation remains separate work for the owners of those files. Route preview and live mutations through one serialized native command lane, while retaining independent preview resource and live baseline owners.

Opening is inspection first, then private construction, then initial actual readback/capture. It must not return UI readiness just because native construction succeeded. Hiding, tab departure, window close or renderer destruction cancels pending preview requests and closes its lease; missed close is covered by lease expiry. Reopening inspects the current identity and creates a fresh preview/target generation. Current live state is read back and retained only for the same valid live baseline. The existing UI policy remains: disabling live mode stops future applies; `Restore Original Eyes` explicitly restores committed changes. No hide/close command mutates the player.

Frame transport needs a fixed host-owned directory per boot and preview generation, one unique filename per sequence, and no overwritten or recycled in-flight file. Native export closes the image before publishing metadata; a completion marker/sidecar is published only afterward. Limit outstanding files to two, acknowledge consumer completion, then remove only exact known owned sequence files after their read handles are closed. On a slow consumer, skip intermediate captures and retain the newest desired request; do not accumulate frames. The renderer facade constructs a Blob only from bounded verified image bytes. No full native export trailer is forwarded.

Reuse the existing PNG validation/normalization rules: retain/hash the full immutable original as evidence, validate signature/chunk bounds/CRC/bounded inflate/IEND, and decode only its valid PNG prefix. V3 exported oversized files with trailing bytes from a preceding file at matching offsets. The current QA consumer records/classifies that suffix, preserves originals and excludes it from decoder bytes. This observed compatibility boundary does not by itself bind pixels to a current request.

Keep production frame publication gated on independently verified request-to-pixel ordering and capture freshness. V3 showed changed pixels after a three-degree camera change and restoration, which is useful evidence; it is not a native completion timestamp. The unmounted UI contract now explicitly accepts a `native-call-interval`, using the host's actual request-send time as a conservative oldest bound and host receipt time as the other bound. It never relabels file modification time, issue time or lease clocks as GPU completion; `renderCompletedAtMs` remains null. Main/preload dispatch and real ordered frame proof are still required.

The renderer samples exact SDK `UGameplayStatics:GetRealTimeSeconds(WorldContext)` (`Engine.hpp:15170`) around `CaptureScene` plus `ExportRenderTarget`. It records `native_clock_id=ue-gameplay-real-time-seconds:<boot>:<world-address>` and the two observed native millisecond values, separately from the lease clock. These may be equal inside one engine tick; equality does not imply zero render duration. Invalid or regressing native clock values reject evidence. The host must map them only into the named native-call interval and preserve its independent send/receipt boundaries and serialized request sequence.

The new controller returns only `captured-evidence` and the native adapter's evidence object, without adding timestamps, byte payloads or ready flags. It keeps no completed-frame buffer. A production facade must additionally reject stale/out-of-order/replayed responses, changed world/pawn/form/wolf/appearance/material/capture/target generations, incorrect actual settings/view readbacks, unknown producer format, and expired capture evidence before sending any frame to the component.

## Bounded next execution

1. Resolve the actual V5 private target display configuration and latent actor cleanup through the separately reviewed V6 probe. Then establish actual private head/hair/skin/eyes, nine required views, isolated lighting, paired cleanup and inventory-independent lifetime.
2. Test the implemented adapter in a short persistent session with repeated preview-only changes; independently inspect live getters to prove preview MID isolation. Keep production availability false.
3. Exercise latest-wins requests and capture under one command lane. Measure native operation wall time, dropped/coalesced requests, decode latency and actual delivered frames at 1024, then a bounded smaller resolution if necessary. The current default cap of 10 captures per second is a safety/performance experiment, not a claim of smooth rotation.
4. Prove actual eye pixels and readbacks correspond for supported presets/values; restore baseline; exercise human/vampire transition and reject stale/wolf generations. Vectors named Leukocoria or CloudyIris alone do not establish a supported general iris picker.
5. Establish the frame freshness contract and bounded publication/ack lifecycle. Test missing/late acknowledgements, renderer crash, hidden menu, app restart, source replacement, partial native failures and cleanup recovery.
6. Only then construct the real session descriptor, wire the host facade and mount the existing component. Run packaged application checks for rotation limits, clipping, colors/presets/restore, hide/reopen, scaled input, compact layout and gameplay-camera isolation.

Nineteen controller groups and twenty-one native-adapter fixture groups pass. In addition to lease/coalescing/failure isolation, the adapter fixtures cover getter-derived floats, preview/live MID separation, accepted tracked live transitions, rejected foreign replacements, movement refresh, camera bounds, post-export camera changes, paired cleanup, partial-file ledgers, capacity acknowledgements, a plain geometry descriptor, the combined renderer/session path and separate native-clock validation. They establish behavior under fixtures, not native rendering or performance. All authored Lua files carry executable signatures and pass syntax checks.

## Diagnostic route if clone construction fails

After the new private actor/target lifecycle is independently proved, another bounded diagnostic could show only the current player's actual mesh components in that owned capture and orbit its camera around observed head/eye landmarks. This would need no original mesh setters or player/gameplay-camera transform changes and would naturally observe currently applied live materials. It must first inspect whether those meshes are visible to this capture without changing their original visibility/owner settings.

This is not an alternate product implementation yet: preview-only eye edits would otherwise affect the player, and private neutral lighting cannot be introduced by illuminating or changing lighting channels on the actual character. Keep it as a separately requested, cleanup-protected rendering diagnostic; do not mount a partial viewer or widen V5 scope around it.
